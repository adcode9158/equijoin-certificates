# Frozen BIRD admission-routing validation

We will use the two earlier pilot databases, financial and formula_1, solely to select routing parameters and the strongest static challenger. Test uses each remaining schema's previously eligible distinct two-table filtered joins. The primary population excludes codebase_community as its Users and Badges overlap STATS. A secondary table reports that schema and the entire former holdout. No new test timings, plans or actual cardinalities are used to select policies. Earlier work already examined these databases. This is a new frozen comparison on previously studied data. The native SQLite decision is whether the original joined intermediate contains at most the budget B. Test two fixed budgets, 100 and 512. B=100 is the primary historical operating point; 512 is a new numeric threshold for this validation. The observed archived cardinality is used solely as an assertion after execution.

The candidate tries a native capped execution for at most V SQLite virtual-machine steps. On exhaustion, interrupt the read-only statement. Enumerate up to K+1 primary keys satisfying the actual dimension predicate. If at most K qualify, count their foreign-key matches up to B+1, using the original fact table without the fact predicate. This count gives a valid upper bound, and is exact when there is no fact filter. A tight upper bound admits the request. Where necessary, apply the actual fact predicate to those candidate keys alone. If more keys qualify, resume with ordinary full capped SQL (from the start). Each invocation is charged for SQLite planning, speculative work, the dimension probe, fact-side counts, fallbacks, and SQL rewriting. Rewriting the probe queries from the provided normalized SQL happens only if the native probe is interrupted. Point access and contiguous B-tree scans are both available to all methods. The result is a budget decision, not an estimate or a returned join.

The training grid is V in {0, 2048, 16384} and K in {1,8,32}, for each budget and index design. Choose the lowest aggregate elapsed training time of these nine recipes. Also consider a deployable selector that may choose plain capped SQL from training. Compare on test against the actual native cap, full native COUNT, and the best fixed no-interrupt certificate alternative selected on the pilot. A matched KEYSET baseline may skip the paper-specific unfiltered upper check on filtered facts and evaluate the actual predicates on all enumerated keys instead. Also compete against this baseline on the identical route. We use alternating orders and at least five rotated test passes, each connection warmed once. Wall time aggregates are sums of the query operation times within each pass, then medians across passes. Rates of rejecting, accepting, attempting certificates, and falling back are reported. Time spent on between-operation logging and reference checks is excluded.

For each database we evaluate its released immutable schema and a matched disposable layout with join-key indexes, covering indexes on simple local predicate columns and their join key, and ANALYZE. Each policy on that layout pays the full measured index build, statistics and index-discovery setup once per stream. Released-layout controls have zero research index build. Data copying to protect the originals is experimental scaffolding and excluded. All methods see the same buffer settings and indexes. We report the training grid cost for learning the route separately from per-deployment build costs, and the effect of parsing all incoming queries at the front end versus only after a slow native query. Streams are sequential, local, read-only and static. Times are not production latencies.
